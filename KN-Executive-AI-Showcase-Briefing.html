🎯 Compelling event - why pro-code, NOT low-code for THIS agent

The trigger: a Sentinel decision moves €100k-€1M of cargo per reroute. The moment Sentinel stops being a UX-enhancer and starts being a system of record for automated high-value decisions, the Copilot Studio surface runs out of road. Five concrete reasons it must be pro-code:

  1. The reroute math IS the IP. calculate_reroute is not an API call to a SaaS. In production it runs scipy/ortools constraint optimization on TMS data, fuel curves, port-pair routings, contract penalties. You cannot write that in Power Fx. You need real Python with real unit tests and real CI.
  2. The model is part of the IP. Copilot Studio uses Microsoft's hosted Copilot model - you can't pick it, can't pin it, can't fine-tune on KN's 10 years of historical reroute decisions. Foundry lets you pick gpt-4.1-mini today, fine-tune tomorrow, swap to Phi-4 or DeepSeek for cost. Sovereignty over the cognitive engine, not just the prompt.
  3. Unit economics flip at scale. Copilot Studio bills per message; Foundry bills per token. At 50 prompts/day Studio wins. At 5,000 reroute checks/day (Sentinel's target volume), Foundry is ~10x cheaper, especially with a tight prompt + small model. Code-first because the math at scale demands it.
  4. The agent is a service, not a chatbot. Same agent will be called from the KN mobile app, from SAP workflows, from Power Automate, from Teams. Copilot Studio agents only live inside Copilot/Teams; Foundry agents are addressable HTTPS endpoints with OAuth. Reuse beyond the chat surface = pro-code.
  5. EU AI Act Annex IV is non-negotiable. Foundry's tracing + App Insights gives every model call, every tool call, every content-safety flag in an audit-grade store. Studio gives you a chat transcript. For a system that makes €100k decisions, the regulator wants the former.

The decision rule for KN: if the agent decides + writes + spends, it's Foundry. If the agent reads + summarizes + assists, Copilot Studio (DEMO-08) is the right tool. Sentinel does both - the read/summarize half could stay in Studio, but the decision half belongs in Foundry. We build it pro-code because the decision is the product.

The numbers that matter for KN:

  • Copilot Enterprise: $39 per user per month (annual, granted seat).
  • Base allowance: 1,000 Premium Requests per user per month.
  • Overage rate: $0.04 per additional Premium Request, billed to the enterprise - not the individual user.
  • Reset cadence: UTC midnight on the 1st of each calendar month. Not the subscription anniversary - tell finance.

Is it pooled? Honest answer: Each licensed Enterprise user has their own 1,000 Premium Requests - unused allowance does not technically migrate to colleagues. But financially it acts like a pool: all overage spend lands in one central enterprise budget that the admin caps, monitors and (optionally) hard-blocks. So if 600 of your 1,000 engineers hardly use Copilot and 100 are power users at 2,500 requests/month, the enterprise just pays 100 × 1,500 × $0.04 = $6,000 in overage - regardless of the 600 "saving" 600,000 requests. Net effect: per-user allowance, enterprise-level budget control.

Central budget controls (the part KN's finance will ask about):

  • Budget scopes: set budgets at enterprise, organization or cost-center level. Enterprise budget acts as a failsafe across all cost centers.
  • Bundled vs per-SKU: a single bundled Premium Request budget (recommended) or separate SKUs for Copilot, Spark and Cloud Agent (separate SKUs since 1 Nov 2025 - better cost visibility).
  • Policy options: monitor only (alerts at 75/90/100%), or stop usage when limit hit (hard block, no overages). Per AI product separately.
  • Upgrade pattern: Business users who consistently exceed 800 Premium Requests are cheaper as Enterprise seats - GitHub flags this in the usage report.
  • Model multipliers: a single Opus-class / reasoning-heavy call counts as multiple Premium Requests; lightweight chat models count as fewer. Admin can restrict model availability per policy.

Same meter, four surfaces: the 1,000 Premium Requests cover everything we just demoed - Copilot Chat in github.com (DEMO-12), Copilot CLI (DEMO-13), VS Code Agent Mode (DEMO-14), the new Copilot App (DEMO-15), plus Copilot Code Review and Coding Agent sessions. Each Cloud Agent session = 1 request × model multiplier. Each steering comment in an active session = +1.

Data & privacy on Enterprise: org code is not used for model training. Period. Same guarantee on Business. Only Free/Pro/Pro+ have opt-in training (with an opt-out switch).
